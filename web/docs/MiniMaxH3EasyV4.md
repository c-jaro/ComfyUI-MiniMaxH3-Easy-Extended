# MiniMax H3 Easy V4

MiniMax H3 conditioning frontend with context-driven visual simplification and native Autogrow reference sockets.

## Mental model

**Mode only chooses output intent:** `Video + audio` or `Audio only (32x32 proxy)`.

**Model explicitly chooses a Loader checkpoint provision:**

- `FL2VA` -> Loader's FL2VA checkpoint
- `REF2VA` -> Loader's REF2VA checkpoint
- Audio-only uses whichever of those two provisions is selected
- prompt structure and connected media never switch the selected checkpoint

Connected inputs choose conditioning. Reference image/video/audio inputs activate the native Reference builder; otherwise Easy uses the text/first-last-frame builder. Starter/template choice sets only the matching Video/Audio Mode and endpoint first/last-frame role; it never changes Model, disables media, or changes connections. Prompt-family mismatch is not a routing error. Current ComfyUI cannot combine first/last-frame and Reference sockets in one native builder, so Easy rejects that physical wiring instead of silently ignoring one family. Model choice, prompt grammar, and downstream LoRAs remain independent of this input constraint.

## Inputs and relevant widgets

Core settings remain serialized while Reference media use ComfyUI's native Autogrow sockets. Inactive controls are synchronized to ComfyUI's real widget `hidden` state so they are not painted at stale canvas positions, while their stored values remain intact.

The visual widget list is reduced automatically:

- `Model`, `Mode`, Prompt, and duration are always visible in that order. `Model` selects the FL2VA or REF2VA checkpoint provisioned by MiniMax H3 Easy Loader.
- Video output resolution/aspect controls appear only in `Video + audio`; the resolution row shows resolved dimensions and decimal megapixels. Current core native 16:9 is `1344 x 768 = 1,032,192` pixels, displayed as `1.03 MP`. A frame-adaptive aspect is labeled as a theoretical pre-alignment megapixel-class range until execution resolves and 32-pixel-aligns the connected image geometry. Audio-only uses an internal 32x32 proxy without changing the stored video-resolution selection. Playback stays fixed at H3 native 24 fps.
- Custom width/height appear only for `Custom exact`; arbitrary serialized/API values are rounded to the nearest 32 pixels.
- First/last-frame policy appears only when those frame inputs are connected.
- `Opening frame resize` appears only when a connected opening frame can actually mismatch a fixed/custom output aspect.
- `Ending frame resize` appears only when a connected final frame can mismatch the resolved output canvas. Its default keeps core H3's center-crop behavior; preserve-full padding and deliberate stretch are explicit alternatives.
- Reference image resolution appears only with a Reference image in normal video mode. `Match output area (predictable token cost)` resamples toward output area and may enlarge without creating detail. `Preserve source detail (2048px short-edge cap; slower)` retains available source pixels up to core's downscale cap and costs more only when the source actually carries more pixels.
- Reference-video resolution/end handling appears only with Reference videos. Resolution choices are class caps: a smaller source is not scaled toward the selected class, although H3's nearest-32 alignment can slightly enlarge or reduce either edge. A lower cap reduces cost only when the source exceeds it. Each connected video also reveals a soundtrack toggle labeled with its compact Reference Video ordinal and `@VideoAudioN` alias. It defaults on; muting it excludes embedded audio from conditioning while preserving frames and timing.

Autogrow reveals the next Reference socket as media are connected. Hiding a widget never removes or rewrites its stored value.

## Prompt editor

Prompt structure selects the editor grammar and validation profile only. Connected inputs select conditioning, and **Model** independently selects the Loader checkpoint. `Reference video N` is one ComfyUI `VIDEO` input: Easy reads its frames and source frame rate, and forwards an exposed synchronized soundtrack only when that video's toggle is enabled. Prompt labels remain separate: `@VideoN` describes editing, continuation, or whole-video timing/structure; `@VideoAudioN` addresses that video's enabled soundtrack; and `@AudioN` addresses standalone Reference audio. Reusing or referencing either audio source still requires an explicit definition and relationship.

The persistent summary reports **Provision**, physical-input **Builder**, and recognized prompt **Grammar** independently. Before a recognizable structure exists it labels the connection-derived editor profile as **Helper**, and mixed Base/Reference markers are reported as mixed instead of being mislabeled as recognized grammar. Provision names the Easy Loader slot only; it is not a capability or compatibility gate. FL2VA provision, Reference builder, and REF2VA grammar may coexist without a mismatch warning or automatic switch. Downstream LoRAs and model patches are applied outside this node and are intentionally not inferred.

The **Guide** button reports the actual number of navigable prompt-writing targets, not a section-completion fraction. It includes missing or empty sections, known Easy placeholders, legacy scaffolds, duplicate/order defects, and required semantic diagnostics that have an exact editable range. Its tooltip lists them and clicking selects the first target. Connection and setting errors remain in the separate Structure diagnostic because they are not prompt text to fill. Known placeholders open their normal choices; a missing or empty section opens explicit scaffold/manual choices and changes text only if the scaffold action is chosen. Guide never changes Mode, Model, connections, builder, grammar, or downstream patches.

Connected inputs and recognized prompt structure determine prompt assistance. Tab inserts/advances fields and Shift+Tab moves to the previous field. Navigation highlights the exact known placeholder range that will be replaced and keeps its menu open. Clicking or moving the caret inside a known placeholder also expands that field to the visible replacement selection; unrelated partial text selections remain ordinary editing selections. Fixed H3 vocabularies expose their documented finite choices; open natural-language fields expose **Custom… first and selected by default**, followed by editable writing presets. Choosing Custom removes the highlighted placeholder, leaves the caret in its place, and returns focus to the editor for free-form typing. This covers visual style, framing/viewpoint, subjects/scenes, actions, speaker identity/voice traits, audio events, ambience/foley, and non-diegetic score components. Dialogue language prioritizes English, Russian, Japanese, Dutch, and French, then offers the remaining stable/common languages. The 11 MiniMax-documented stable languages are distinguished from additional variable-support helpers, and Custom remains available. Exact dialogue/lyrics and visible-text fields use Custom rather than fabricated content.

Clicking a completed dialogue tag such as `[Russian]` shows the current value plus the full replacement list; typing an unfinished tag still filters. Clicking a completed plain-text preset such as `high angle` or `extreme close-up` reopens the choices that originally filled that field, and **Edit current text** selects the phrase without changing it. “Quick language tags” is only a UI convenience group, not a model preference. `<scenetrans>` is only for the same line continuing across a shot cut, with the marker at the connection point in both fragments and explicit audio-continuity wording. `<cutoff>` is only for a line truncated by the end of the generated video, not an ordinary interruption or shot cut.

Reference `summary` is one short continuous paragraph. `overall_soundscape` is one continuous paragraph of 1–4 sentences, and `non_diegetic_music` is one continuous paragraph of 1–3 sentences. Blank lines still separate top-level sections. Reference `detailed_description` keeps its one-to-two-sentence style opening before `[Shot 1]` and then the shot timeline.

`@`, `[`, `#`, `(`, and `:` open contextual choices. On an empty prompt, Tab offers Custom plus separate T2V, I2V, L2V, FL2V, R2V, T2A, R2A, I2A, V2A, and A2A starters; template choice sets only its matching Video/Audio Mode and endpoint first/last-frame role. It never changes Model or connections. Reference starters begin with an editable bracketed task type chosen from MiniMax's six documented relationships. T2A/R2A/I2A/V2A/A2A are Easy audio-only proxy template names, not additional MiniMax task types; their prompt bodies retain the applicable Base or full-reference grammar. Hover or Arrow keys move the visible selection without reordering or resizing the option rows; Arrow navigation is isolated from ComfyUI/global key handling so it cannot dismiss the menu before a choice is made. The fixed inspector sits in its own non-overlapping row below the scrollable options; click or Enter inserts the active choice. Selecting a raw `@ImageN`, `@VideoN`, `@VideoAudioN`, `@AudioN`, or `@SubjectN` immediately opens a second-stage role/template menu. Before any structure exists, Reference inputs offer role choices that create the complete six-section prompt, put the selected definition in `subject_definitions:`, and preserve surrounding draft prose in the first target-timeline shot. A bare `@` produces an explicit empty-state message when nothing usable is connected/defined, with the corrective instruction shown in the inspector. Blocking validation is shown above the textarea as one compact status row. Multiple issues expose previous/next arrows and an `n/N` counter directly beside that warning, plus a ▸/▾ marker showing that details can be expanded. The detail stays collapsed until the warning is clicked. Low-value examples that only repeat a section/header warning are omitted; useful syntax/content suggestions appear as `Try:` only when they add information. Changing issues does not move the textarea selection. The autocomplete panel stays directly below the textarea and expands the node downward while open, so it never overlays the controls below or steals height from the text editor. Friendly aliases remain validator-aware in the editor and are compiled for execution, including payload-dependent audio ordinals finalized at execution, but there is no separate Compiled Prompt UI or workflow output.

On ordinary unstructured prose, the starter menu adds **Wrap draft** actions. Base wrappers preserve the prose in `integrated_multimodal_description`; Reference wrappers let the user place it in `summary` or `detailed_description`. When a draft already contains later shots, L2V/FL2V wrappers bind the final Picture to the actual last shot instead of assuming `[Shot 1]`. Blank-template actions remain separate and explicitly say they replace the draft. In a Reference definition field, **Relationship builder** actions fill a definition, recommended official task type, summary relationship, matching retention row, and point-of-effect text as normal editable prompt text. Visual bundles replace the generic first-shot action field so they do not duplicate it or put more action after their own endpoint; timeline/vocal audio clauses remain additive in `detailed_description`, ambience/SFX relationships go into `overall_soundscape`, and audience-only score relationships go into `non_diegetic_music`. Optional next-definition and next-retention fields remain until **Done** is chosen.

The `@` menu includes `@VideoAudioN` for enabled video soundtracks alongside `@ImageN`, `@VideoN`, standalone `@AudioN`, and `@SubjectN`. For endpoint first-line alignment defects, **Apply structural fix** performs the deterministic repair through the editor's undo-preserving replacement path and leaves user prose intact.

This covers the deterministic part of the local/API prompt gap: published section shape, task/retention vocabulary, reference-role consistency, aliases, and native ComfyUI H3 media interleaving. Exact remote-API parity is not claimed because the public guides do not establish whether the hosted service applies additional proprietary prompt rewriting, and the local Qwen component is used as an encoder rather than a text generator.

For the Reference audio-proxy starters, I2A abstracts visible image content through `@SubjectN`, V2A uses `@VideoN` only for whole-video structure, and A2A uses standalone `@AudioN` for the audio relationship. V2A exposes `@VideoAudioN` after the connected video's soundtrack is enabled, but the starter never infers audio reuse from a video's mere presence.

Connected inputs, not Model, choose conditioning. Any Reference image, video, or audio activates the native Reference builder; otherwise the text/first-last-frame builder is used. Current native H3 builders cannot combine Reference media and endpoint frames, so the node rejects both physical families being connected at once.

## Loader relationship

Easy Loader exposes FL2VA and REF2VA checkpoint provisions. **MiniMax H3 Easy -> Model** explicitly chooses which provision runs, including in Audio-only mode.

The Easy node does not own a sampling-seed control. The bundled example's downstream `RandomNoise` node is set to seed `0` with automatic randomization after generation; set that node to fixed when repeatable sampling noise is required. Current ComfyUI H3 separately uses a fixed internal seed `0` for its 0.1% visual-reference conditioning-noise augmentation. That internal seed is not the sampler seed, and audio-reference augmentation adds no noise.
